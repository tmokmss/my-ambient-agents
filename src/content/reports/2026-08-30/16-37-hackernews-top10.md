## 1. [Creepy Crawlies](https://people.kernel.org/monsieuricon/creepy-crawlies)

**Score:** 248 | **Comments:** 95 | [Post](https://news.ycombinator.com/item?id=49491791)

git.kernel.org の運営者が、AI学習用データを収集するスクレイパーによる深刻な負荷問題を報告している。日々約600万リクエストの66%がスクレイパーによるもので、全トラフィックの98%を占めると推定され、5つの地域サーバーで常時14〜16コアがその対応に費やされている。計算難題型の認証システム「Anubis」を導入したが、スクレイパー側がこれを突破し始めており、根本的な解決策がないまま機能制限による対応が避けられない状況だという。

### Key Discussion Points

- **semiquaver**: Anubis の前提である「大量の計算コストがスクレイパーに負担になる」という考え自体が誤りで、まともな難易度設定ではスクレイパーにとって大した障害にならないと指摘
  - **wongarsu**: 最適化されたJS実装とブラウザのCカーネルの間に3桁の性能差があることが問題の本質ではないか、両者が同オーダーに収まれば実用的な仕組みになり得ると反論
  - **smallerize**: スクレイパー側はより多くのリクエストを送り、その分の計算コストも負担しているという点を指摘
- **tptacek**: Tavis Ormandy が約1年前にAnubisの限界を予言していたことを紹介、高性能スクレイパーには対処しきれず解決策として定着しなかったと総括
  - **nneonneo**: 反論として、カーネルのケースではスクレイパーの66%が直接弾かれており効果はあるとしつつ、真の問題は住宅用プロキシSDKを悪用したスマートTV等の「プロキシ艦隊」化にあると指摘
- **Demiurge**: 自身が運営する人気ゲームサイトでの類似経験を共有、オンラインユーザーカウンタが偽の同時接続数によって歪められた事例を紹介
  - **anal_reactor**: 公共資源が悪用される「コモンズの悲劇」と同じ構造だと指摘
- **easton**: shallow clone がなぜ「悪」とされるのか疑問を呈するコメント
  - **jacobvosmaer**: 通常のクローンはサーバー上のデルタ圧縮データを再利用できるが、shallow clone は要求された深さ以外のデータ転送を禁じるため、事前計算されたデルタチェーンが使えなくなり非効率になると説明

## 3. [Omarchy: Any User Process Can Escalate to Root](https://0xcc.io/posts/omarchy-root-creds/)

**Score:** 15 | **Comments:** 3 | [Post](https://news.ycombinator.com/item?id=49499854)

Linuxディストリビューション「Omarchy」のデフォルトDocker設定に、パスワードやsudoなしで任意のユーザープロセスがrootに昇格できる脆弱性が発見された。原因はデフォルトユーザーが`docker`グループに所属していたことで、Dockerデーモンはroot権限で動作しSocket経由でホストのファイルシステム全体をマウント・操作可能なため、AIコーディングエージェントやブラウザ、エディタなど通常セッション内のほぼ全プロセスがroot権限を得られる状態だった。発見者は責任ある開示プロセスを通じて報告し、4.0.1で修正済み。opt-outではなくopt-inにすべきだったという、セキュリティ既定値設計への批判も述べられている。

### Key Discussion Points

- **darkwi11ow**: 2026年にもなってなぜrootless podmanを使わないのか、Podmanの方が今ではDockerより優れていると指摘

## 8. [Arbitrary code execution in QubesOS via copy-to-VM error reporting backchannel](https://www.qubes-os.org/news/2026/08/29/qsb-118/)

**Score:** 146 | **Comments:** 61 | [Post](https://news.ycombinator.com/item?id=49496918)

Qubes OSのセキュリティ情報QSB-118。`qvm-copy-to-vm`ツールにおいて、dom0へファイルをコピーする際のエラー報告処理がファイル名をシステムコマンドとして扱う際、非ASCII文字のみを除去しシェルメタ文字（`$`や`;`など）を除去していなかったため、悪意あるqube（仮想マシン）がファイル名にコマンドを注入しdom0上で実行できる脆弱性。攻撃成立にはユーザーが侵害されたqubeへファイルコピーを開始する必要がある。修正版 qubes-core-dom0-linux 4.3.22 の適用が推奨されている。

### Key Discussion Points

- **msm_**: QubesOSの攻撃対象領域は非常に小さく設計されているにもかかわらず、こうした脆弱性が見つかったことに驚きを表明。この脆弱性はdom0からのcopy-to-VM実行時のみ発生する点を補足
- **sdcfgy**: OpenBSDのTheo DeRaadtによる過去の発言を引き合いに出すコメント
- **grommz**: QubesOS創設者のJoanna Rutkowskaは2018年にプロジェクトを離れており、脆弱性の原因となったコードは後継のMarek Marczykowski-Góreckiによるものだと説明。Joannaが以前「Intel x86 considered harmful」という論文を書いていたエピソードにも言及
- **zby**: QubesOSの実績には感銘を受けており、金融関連の専用ノートPCとして利用中。グラフィックのハードウェアアクセラレーション欠如が普及を妨げている最大の要因ではないかと指摘
- **Naru41**: 技術的な指摘として、`untrusted_filename`は少なくとも文字列長を引数として受け取るべきだったとコメント
